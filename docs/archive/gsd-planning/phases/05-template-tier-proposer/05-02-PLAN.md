<objective>
Ship SC-4 for Phase 5: a hermetic, cross-platform (Git Bash Windows + Linux + macOS) simulation gate that proves the template-tier proposer's end-to-end contract — 4 flavor paths produce applyable diffs, and 3 rejection paths (multi-file violation, non-template path, malformed diff) + 1 input-validation path are all caught by the proposer's gates.

Mirror Phase 4 Plan 02's structure verbatim (per CONTEXT §analogous patterns): per-scenario subshell, PATH-injected stub CLI with canned responses, primary-only counter footer `N/N scenarios passed`, trap-based cleanup, zero new dependencies beyond bash + jq + git (which `git apply --check` requires anyway).

Purpose: Phase 8's PR emitter will call the template-tier proposer in production. The simulation proves (a) the 4 flavor paths work with realistic Phase 2 eval-report shapes, (b) the D-09 single-file + path-prefix gate rejects malicious or drift-induced bad diffs, (c) the D-10 git-apply-check gate rejects structurally malformed diffs, and (d) the D-03 required-input gate fails fast when callers (Phase 8 or manual) omit a required env var. Without this gate, Plan 01's shipped code is theory — the simulation makes the contract enforced by CI.

Output:
- `tests/template-proposer-simulation.sh` — the gate (executable, ~400-500 lines)
- `tests/fixtures/eval-failures/*.json` — 4 synthetic eval-failure reports (one per flavor, targeting different templates for mutation-target diversity per CONTEXT §specifics)
- `tests/fixtures/templates/*.md` — 4 verbatim copies of real dev-review templates (hermetic mutation targets that do NOT pollute the real skills/dev-review/templates/ during test runs)

Non-goals explicitly out of scope:
- Real Opus invocation (hermeticity is the entire point — CONTEXT D-13)
- Semantic grading of the diff content (human-graded per CONTEXT §SC-4 — "this test isn't fully automatable")
- Scoring diffs for fitness impact (Phase 8)
- Any modification of `lab/pel/proposer/template/**`, `lab/pel/classifier/**`, `skills/dev-review/templates/**`, or `lab/pel/proposer/policy/**` (Phase 6 parallel work — separate worktree)

### Stub claude CLI contract (invented here, mirrors Phase 4's CLASSIFIER_STUB_FILE convention)

A PATH-injected bash shim at `$TEST_DIR/bin/claude`:
- Reads canned response bytes from a file whose path is in `$PROPOSER_STUB_FILE`
- Consumes its stdin (drains the prompt-file redirect)
- Writes a fingerprint marker to `$PROPOSER_STUB_MARKER` (optional, for future negative-path proofs)
- Supports `--version` probe for any `require_claude_cli` path
- On `$PROPOSER_STUB_EXIT` set, exits with that code (simulates non-zero Opus call if ever needed)

Env var prefix `PROPOSER_*` (not `CLASSIFIER_*`) keeps the stub independent from the Phase 4 stub — both simulations may coexist in CI without env collision.

### Phase 2 scorer JSON schema (what eval-failure fixtures mirror)

From `evals/score-run.sh` + `evals/fixtures/mock-scores.json`, the proposer's
eval-report input is a JSON object (or array of objects) with at minimum:

```json
{
  "case_id": "04-hallucination-trap",
  "status": "ok",
  "run_id": "20260417-091500",
  "composite": 0.62,
  "scores": {
    "robustness": "PASS",
    "convergence": "PARTIAL",
    "plan_quality": "PASS",
    "execution_fidelity": "FAIL",
    "verify_accuracy": "PASS",
    "cost": "PARTIAL",
    "cross_ai_diversity": "PASS"
  },
  "details": { ... }
}
```

Fixtures MAY additionally include a `target_template` annotation field (non-standard —
added for fixture clarity only; the real scorer does NOT emit this field). The proposer
itself treats the whole report as opaque JSON blob; it never keys on specific fields.

### Hermetic fixture invariant

- `tests/fixtures/templates/*.md` are byte-identical copies of
  `skills/dev-review/templates/*.md` (pinned by `diff -q` at test setup).
- This means the proposer, when given `PEL_TEMPLATE_PATH=tests/fixtures/templates/X.md`,
  is mutating a DISTINCT file from the real template — the real skills dir is
  NEVER touched by the test. Plan 01's D-09 allowlist permits both prefixes
  for exactly this reason.
- Fixtures are committed to git so the test is deterministic across clones.
