<objective>
Ship the Phase 7 code-tier mutation proposer: a self-contained bash module under `lab/pel/proposer/code/` that consumes eval-failure feedback + a target code file + a flavor pick and emits a single-file, budget-capped, canary-validated unified diff to stdout. This is the hardest of the three proposer tiers because mutations target executable shell code — a bad mutation breaks the runner, not just a template. Phase 7 therefore introduces three capabilities absent from Phases 5/6: (1) sandbox isolation via `git worktree add`, (2) a canary smoke-test suite that runs AFTER mutation but BEFORE scoring, and (3) diff budget + file allowlist enforcement.

Purpose: Phase 7 completes the three-tier proposer surface (template/policy/code). Phase 8's PR emitter calls this proposer for code-tier mutations. The canary suite is the trust boundary between "LLM proposed a change" and "LLM proposed a change that doesn't break the runner." Without canary, a single bad mutation could silently break agent-bouncer or dev-review and waste an entire eval scoring cycle. The sandbox guarantees the live checkout is never modified — if canary fails, the worktree is removed and the live repo is untouched.

Output:
- `lab/pel/proposer/code/prompt.md` — code-tier mutation prompt (shell-aware, flavor-biased, budget-aware, ~50-80 lines)
- `lab/pel/proposer/code/adapter.sh` — self-contained Opus-4.7 adapter (6-placeholder prompt composition + claude CLI invocation + diff capture)
- `lab/pel/proposer/code/allowlist.txt` — explicit file allowlist (3 paths)
- `lab/pel/proposer/code/canary.sh` — canary smoke-test suite (5 scenarios, distinct exit codes, PATH-injection stubs)
- `lab/pel/proposer/code/proposer.sh` — public entry point (env validation, allowlist gate, diff budget gate, sandbox setup, git apply, canary orchestration, state.json, cleanup)

### Exit codes (D-21 taxonomy)

- `0` -- success (diff emitted to stdout, canary passed, state.json written)
- `1` -- input validation failure (missing env var, invalid PEL_FLAVOR, invalid model, path traversal)
- `2` -- claude CLI missing / auth failure / Opus call non-zero / empty response
- `3` -- malformed diff (not applyable via `git apply --check`)
- `4` -- single-file constraint violation (diff touches more than one file)
- `5` -- allowlist violation (diff targets a file not on `allowlist.txt`)
- `6` -- diff budget exceeded (mutation exceeds N=20 lines changed)
- `7` -- canary failed (mutation applied but runner broke; state.json has details)
- `8` -- sandbox setup failed (`git worktree add` failed)

Exit codes 5/6/7/8 are new to Phase 7. They are load-bearing for Phase 8's PR
emitter: 5/6 = pre-flight rejection (no sandbox touched); 7 = mutation tested and
rejected; 8 = infrastructure failure.

### Pre-flight gate order (D-07)

After the LLM emits a diff and BEFORE sandbox creation:

1. Parse diff headers -> extract file targets
2. Single-file check: count unique targets, must == 1 (exit 4)
3. Allowlist check: the single target must appear in allowlist.txt (exit 5)
4. Budget check: count +/- lines (excluding --- +++ @@ headers), must <= 20 (exit 6)
5. `git apply --check` dry-run against REPO_ROOT (exit 3)

Only diffs surviving ALL five checks proceed to sandbox creation.

### Sandbox lifecycle (D-01, D-02, D-03)

1. `SANDBOX_PATH=$(mktemp -d "${TMPDIR:-/tmp}/pel-code-sandbox-XXXXXX")`
2. `git worktree add "$SANDBOX_PATH" HEAD` (detached HEAD from current state; exit 8 on failure)
3. `git apply` the diff inside the sandbox (cd into sandbox first)
4. Run `canary.sh "$SANDBOX_PATH"` (exit 7 on non-zero)
5. Write `state.json` to `$SANDBOX_PATH/state.json`
6. Emit diff to stdout
7. Cleanup: `git worktree remove --force "$SANDBOX_PATH"` in trap EXIT handler

### D-12 self-containment invariant

Zero `source` / `.` statements in `lab/pel/proposer/code/**` resolve outside
that directory. The ONLY sibling source is `proposer.sh`'s
`source "$SCRIPT_DIR/adapter.sh"`. No reach into `lib/co-evolution.sh`,
`lab/pel/classifier/**`, `lab/pel/proposer/template/**`, `lab/pel/proposer/policy/**`,
or runner internals.

### Canary contract (D-08, D-09, D-10)

`canary.sh` receives sandbox worktree path as `$1`. Runs 5 scenarios sequentially.
Returns 0 if all pass; distinct exit code 1-5 on failure (proposer translates to exit 7).

| Scenario | Exit code on failure | What it checks |
|----------|---------------------|----------------|
| source-survives | 1 | `bash -n lib/co-evolution.sh` + `source lib/co-evolution.sh` |
| helper-signatures | 2 | grep for 4 function definitions still present |
| agent-bounce | 3 | agent-bouncer e2e with stub claude/codex |
| dev-review-plan-only | 4 | dev-review --plan-only with stub agents |
| one-eval-case | 5 | simplest eval fixture runs to completion |

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User shell -> proposer.sh | $1 task hint and PEL_* env vars enter from an untrusted shell; must be validated before use. |
| proposer.sh -> adapter.sh | Trusted intra-directory sibling boundary (sandboxing enforced at proposer.sh; adapter trusts its caller). |
| adapter.sh -> claude CLI | claude process runs outside our trust boundary; its output is opaque bytes until validated. |
| claude CLI -> pre-flight gates | Opus-emitted diff text is untrusted LLM output; pre-flight gates (parse, allowlist, budget, git apply --check) decide acceptance. |
| proposer.sh -> sandbox worktree | Sandbox is a separate filesystem tree; mutations are isolated from the live checkout. |
| sandbox -> canary.sh | Canary runs inside the sandbox with PATH-injected stubs; no real API calls. |
| proposer.sh stdout -> Phase 8 caller | Phase 8 scoring loop consumes stdout as a diff; all unsafe content is gated above. |
| state.json -> Phase 8 | Phase 8 reads state.json from sandbox root; trusted because proposer.sh authored it. |
