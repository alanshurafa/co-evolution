A desktop operations dashboard reads the state of scheduled jobs, background
services, and local development servers on a single workstation. Read-only
status collection works. Every mutating action — stopping a runaway process,
restarting a service, shutting down a stray development server — is disabled,
because the dashboard runs unprivileged and has no trusted way to prove that a
requested action is one an operator actually authorized.

Plan the design and rollout of a privileged helper that closes this gap. Cover
the trust boundary between the unprivileged front end and the elevated helper,
how the set of permitted targets is declared and validated, protection for
targets that must never be touched, tamper-evident logging, a dry-run mode, and
a staged rollout that begins with one low-risk action class and widens only
after a soak period.

Produce a plan of roughly 600 words.
