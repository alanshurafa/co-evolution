Co-Evolution: cross-vendor review benchmark for coding agents

Does a second model reviewing the first one's patch produce more resolved issues than either model alone, and at what cost? Every configuration is an implementer and a reviewer drawn from different vendors, run on the same frozen tasks, scored by the official evaluator, and shown with its uncertainty.

Read this before the table

50 tasks is a probe, not a ranking. One task is 2 points, and the intervals on every row say how far two rows have to be apart before the difference is more than noise. Rank(UB) ties every row whose interval overlaps the leader's.

Rows from run base50 are shown with a flag rather than hidden: Frontier tier partial run (Fable, gpt-5.6-sol). Generated from a dirty harness worktree and stopped part way through A and B; kept as-is and shown with this flag, never as a headline.

Unfinished rows (glm-5.3-flash (single-shot), kimi-k3 (single-shot), fable solo, fable → gpt-5.6-sol, glm-5.3-flash (single-shot), kimi-k3 (single-shot)) are scored against the tasks they actually ran, because a task an arm has not reached is not a failure; they carry no Rank(UB).

Cost marked "est." prices a Codex phase from a total-only token figure with the split recorded in the pricing file; the range under it prices the whole total at the cached-input and output rates. A phase captured with --json is priced exactly.

These numbers are not comparable to published full-500 SWE-bench Verified scores. The two tiers are listed separately because they are not the same test.

Pass rate against cost

Agentic rows with a complete run and a fully priced cost. The line joins the Pareto frontier: no row above and to the left. Whiskers are the Wilson interval. On the cost axis the frontier is sonnet solo, sonnet → gpt-5.6-terra, gpt-5.6-sol solo, gpt-5.6-terra solo.

Paired contrast

Same tasks, same seed, compared task by task. The discordant tasks are the only ones that carry information about which arm is better; the exact McNemar test asks whether their split could be a coin flip. Cost per net flip is what the second arm paid for each task it gained on balance.

Methodology and integrity

  • Evaluator. Official SWE-bench harness pinned at 7a21e0577295, dataset princeton-nlp/SWE-bench_Verified at revision c104f840cc67, both from benchmarks/code/external-sources.lock.json.
  • Gold canary. A gold patch resolved 1/1 before any generated prediction was scored. Report: benchmarks/results/code/evaluation/gold.gold-canary-20260904T193109Z.json.
  • Cost. Claude cost is the CLI's own figure. Codex, GLM and Kimi are priced from the token counts in each cell's logs at the list prices in benchmarks/code/pricing.json (recorded 2026-09-04). A row is "fully priced" only when every seat that ran has a priced figure; otherwise the cost column says incomplete rather than showing a smaller number.
  • Uncertainty. Wilson score, 95% per row; exact two-sided McNemar on discordant tasks per pair; a 2000-draw bootstrap over repo, task, seed for the paired delta; Rank(UB): 1 + number of arms whose interval lower bound exceeds this upper bound. Code: benchmarks/site/stats.py.
  • Provenance badges. "official evaluator" and the gold canary say how a row was scored; "we ran it" says who generated the patches; "clean tree" or "dirty tree" is what the cell manifests recorded about the harness, and "harness unrecorded" means the run predates that record; "flagged" carries the run registry's note and keeps the row out of any headline.
