### Exit code taxonomy (from CONTEXT D-21)

| Code | Meaning |
|------|---------|
| 0 | Success — diff emitted, canary passed, state.json written |
| 1 | Input validation failure (missing env var, invalid flavor/model/path) |
| 2 | claude CLI missing / auth / call failure / empty response |
| 3 | Malformed diff — does not apply via `git apply --check` |
| 4 | Single-file constraint — diff touches >1 file |
| 5 | Allowlist violation — diff targets non-allowlisted file |
| 6 | Diff budget exceeded — >20 lines changed |
| 7 | Canary failed — mutation applied but runner broke |
| 8 | Sandbox setup failed — `git worktree add` failed |

### Stub claude CLI contract (mirrors Phase 4/5/6 pattern with CODE_PROPOSER_ prefix)

A PATH-injected bash shim at `$TEST_DIR/bin/claude`:
- Reads canned response bytes from `$CODE_PROPOSER_STUB_FILE`
- Consumes stdin (drains prompt-file redirect)
- Writes fingerprint to `$CODE_PROPOSER_STUB_MARKER` on invocation
- Supports `--version` probe
- Honors `$CODE_PROPOSER_STUB_EXIT` for forced-exit scenarios

Env var prefix `CODE_PROPOSER_*` (not `PROPOSER_*` or `CLASSIFIER_*`) keeps the stub independent from Phase 4/5/6 stubs — all four simulations may coexist in CI without env collision.

### Canary stub infrastructure

The canary.sh runs 5 scenarios inside the sandbox worktree. For hermetic simulation, the test must provide minimal stubs so canary scenarios 3-5 (agent-bounce, dev-review, eval-case) can pass without real agent infrastructure:

- `$TEST_DIR/bin/codex` — stub that exits 0 with minimal output
- Agent-bouncer and dev-review stubs via PATH injection already handle scenario 3-4
- Scenario 5 (one eval case) needs a minimal eval fixture in the sandbox

Canary scenarios 1-2 (source-survives, helper-signatures) work without stubs because they only test the mutated file's syntax and exported functions.

### Sandbox worktree lifecycle

1. proposer.sh creates worktree at `$TMPDIR/pel-code-sandbox-XXXXXX` via `git worktree add`
2. Mutation applied inside worktree via `git apply`
3. Canary runs inside worktree
4. state.json written to worktree root
5. On success: diff emitted to stdout, worktree left for Phase 8's PR emitter
6. On failure: worktree cleaned up via trap

The simulation must verify state.json contents after happy-path scenarios and verify worktree cleanup after rejection scenarios.
