       ```bash
       # list_available_lab_modes <lab_root> → prints comma-separated subdir names sorted.
       # Prints "(none)" when <lab_root> absent or empty. Always exits 0.
       list_available_lab_modes() {
         local lab_root="${1:?list_available_lab_modes requires a lab_root}"
         if [[ ! -d "$lab_root" ]]; then
           printf '(none)'
           return 0
         fi
         local modes
         modes=$(find "$lab_root" -mindepth 1 -maxdepth 1 -type d -printf '%f\n' 2>/dev/null \
                 | sort | paste -sd, -)
         if [[ -z "$modes" ]]; then
           printf '(none)'
         else
           printf '%s' "$modes"
         fi
         return 0
       }
       ```
       Note: `find -printf` is GNU-find-specific. Git Bash for Windows ships GNU find. On macOS, `find -printf` is absent — fallback to `basename` loop. Implement BOTH paths:

       ```bash
         if find --version 2>/dev/null | grep -q GNU; then

           # macOS fallback — no -printf support
       ```

       ```bash
       # dispatch_lab_mode <mode> <lab_root> <argv...>
       #   Validates mode, resolves <lab_root>/<mode>/entry.sh, exec's it with remaining argv.
       #   Never returns on success. Dies on invalid token, unknown mode, or missing entry.sh.
       #   T-03-02-01 + T-03-02-03 mitigation: mode token is validated BEFORE any fs op.
       dispatch_lab_mode() {
         local mode="${1:?dispatch_lab_mode requires a mode}"
         local lab_root="${2:?dispatch_lab_mode requires a lab_root}"
         shift 2
         if ! validate_lab_mode "$mode"; then

           die "unknown --lab mode: $mode. Available: $available"
         fi
         # exec replaces the current process — the lab inhabitant owns stdout/stderr/exit.
         exec bash "$entry" "$@"
       }
       ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user-argv→runner | `--lab <mode>` reads untrusted `<mode>` from CLI argv. Used to construct a filesystem path `lab/<mode>/entry.sh` that the runner `exec`'s. |
| runner→lab-inhabitant | Once validated, `dispatch_lab_mode` `exec`'s `lab/<mode>/entry.sh` with runner's full privileges. Lab inhabitants inherit runner trust. |
| default-invocation→runtime | Users who never pass `--lab` expect zero behavior change (L-03 byte-parity). Arg-parser regressions cross this boundary silently. |

## STRIDE Threat Register (ASVS L1; security_enforcement=true, block-on-high=true)

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Tampering | `dispatch_lab_mode` mode-token path construction | mitigate | `validate_lab_mode` enforces `^[a-zA-Z0-9_-]+$` BEFORE any `$lab_root/$mode` path is constructed. Task 1 verifier asserts rejection of `../etc`, `foo/bar`, `foo;rm`, `foo$bar`, empty. Task 3 Scenario D exercises both runners end-to-end with `../etc` and `foo;rm`. Defense-in-depth: `exec bash "$entry" "$@"` passes `$entry` as a single positional — no eval, no word-splitting. |
| T-03-02-02 | Spoofing | Silent fall-through on unknown mode | mitigate | L-04 fail-fast: `dispatch_lab_mode` dies with `unknown --lab mode: <m>. Available: <list>` when `<lab_root>/<m>/entry.sh` does not exist. Task 3 Scenarios B + C verify both runners emit the error on end-to-end invocation. Without this mitigation, a user could typo the mode name and get silent default behavior while believing they are testing lab code — gaslighting risk. |
| T-03-02-03 | Elevation-of-Privilege | `exec` of `lab/<mode>/entry.sh` with runner privileges | accept (contract) | Documented in `lab/README.md` §Sandbox guarantee (Plan 01): lab inhabitants run with runner's privileges and cannot modify master directly — only via emitted PRs. Each lab inhabitant ships its own sandbox/canary enforcement in its own phase (e.g., PEL code-tier in Phase 7). Phase 3 writes the contract; enforcement ships per-inhabitant. |
| T-03-02-04 | Tampering | Argv-position bug — `--lab` parsed after `--` terminator | mitigate | Task 2 acceptance asserts `grep -n "^[[:space:]]*--lab)"` line number is less than `grep -n "^[[:space:]]*--)"` line number in BOTH runners. A future refactor that moves the arm fails the gate. |

| T-03-02-08 | Tampering | Shared-helper code path used by both runners — one fix covers both | mitigate | `dispatch_lab_mode` in `lib/co-evolution.sh` is sourced by both runners. Task 1 unit tests verify helper behavior; Task 2 + Task 3 verify integration. Single-point-of-truth eliminates drift between runners. |
