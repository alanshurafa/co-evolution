## Lessons captured

- **Hermetic tests that stub the full claude CLI surface miss adapter-to-LLM-output contract gaps.** Six dogfood-caught bugs (#5 #6 #7 #9 #10 #11) all trace to this root cause. v1.3 should harden the hermetic claude stub to validate real-CLI flag-combo rejects (main==fallback, etc.) and to emit the same output-shape variations Haiku/Opus actually produce (fence wrapping, omitted echo-back fields, stochastic field ordering).
- **Validation checks must match prompt ground truth.** Bug #11 was "validate Haiku's echo of a path the prompt never substitutes" — the validation was meaningless. Adapters should either (a) substitute all fields they validate, or (b) not validate what the prompt doesn't provide.
- **Codex's built-in shell tool has a ~124s idle timeout** that kills long-running commands silently. PowerShell `Start-Process -WindowStyle Hidden` is the dispatch path for multi-minute PEL runs from inside Claude Code.
- **Real-scorer cost is non-trivial:** ~80 min and ~$10-15 per PEL invocation if all 9 eval cases run. The `PEL_RUN_EVALS_OVERRIDE` hook (added during Phase A for test purposes) turned out to be the right dispatch for dogfood too.
